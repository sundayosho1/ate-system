# Offline workspace help and troubleshooting

## Researcher workflow

Obtain genuine offline source bindings from the accepted checkout and trusted review process. Do not
fabricate hashes, actor approval, data or certificates. Choose a bounded knowledge subset and its
genuine manifest source records. Supply accepted immutable reporting evidence separately.
Authenticate the release descriptor against trusted context, compose, inspect the seven
owner-qualified axes, then query or export. Missing report/source evidence remains
UNKNOWN/UNSUPPORTED; an empty result is not source absence.

Use accepted `@ate/research-insights` glossary/search/catalogue contracts for standalone static
search. Workspace linking does not create a new scientific or source-of-truth authority. Snapshot,
HEALTHY, READY, COMPLETE and ACK must be explained by their owner, version, temporal scope and
commitment; C-OP01 remains open. No attention recommendation grants a trading permission or P28
opportunity state.

## Configuration and administration

`createWorkspacePolicy` permits only lower integer W1 ceilings. Omitted policy retains defaults.
Weaker overrides never expand an embedded view policy. Guidance describes source declarations, not
effective running configuration. There are no setters, IAM grants, approval commands or silent
refreshes. A displayed identity is not authenticated authorization. Preserve maker/checker and
source-owner approval boundaries externally.

Read A26-Q01 admission-starvation disclosure. For scanner consumers retain totalRequests and
explicit offsets; nextOffset alone is insufficient (A26C-L01). No running scanner is queried or
modified by the workspace.

## Reasons and troubleshooting

WORKSPACE:INPUT_INVALID identifies invalid structural/schema/field data. POLICY_INVALID is
unsupported/raised policy. SOURCE_BINDING_MISMATCH or RELEASE_AUTHENTICATION_UNESTABLISHED requires
genuine source context, not another hash guess. REFERENCE_UNAVAILABLE means the bounded supplied
inputs cannot establish a link. EVIDENCE_IDENTITY_CONFLICT rejects invalid/conflicting report
evidence. BUDGET_EXHAUSTED rejects before exceeding admitted work; retrying inside an operation does
not restore credits. CANCELLED is cooperative pre-admission cancellation, not preemptive
interruption. CONSISTENCY_UNESTABLISHED means no generation-pinned cross-owner read guarantee.

Do not turn an upstream INPUT_INVALID into a definite budget diagnosis: OPEN D-E-L01 remains.
Preserve original reason, owner, operation, phase, time, commitment and evidence identity when
escalating. A manual improvement proposal requires genuine evidence, human review, a separate owner
implementation instruction, post-change verification and separate acceptance. It cannot change state
itself.

## Export and security

Safe export omits raw native bodies, subjects/labels, proposal text and locators. Original
workspace/report and redacted projection fingerprints remain distinct. Do not publish internal view
objects as a safe export. Keep trusted-root/single-writer restrictions. No automatic purge,
arbitrary file discovery, credential ingestion, server or live broker feature is available.

## Developer validation

Use root exports. Keep new tests and code within the39approvedpaths. Run frozen install, two-worker
verify, full/prod audits, dependency graph, secret hygiene and architecture/mutation controls.
Preserve all existing source fingerprints and accepted governance bytes. Technical/governance
acceptance are PENDING; production, Windows durability and live trading are not certified.

## Reconstructed views and section filters

Keep original bounded `knowledgeSourceEvidence` with a workspace view. Missing source evidence,
invalid catalogue relationships, contextual links or headers reject on query, diagnostics,
improvement views, handover and export. Rehashing invalid data does not validate it. Recompose a
legacy view only from its genuine retained original source inputs; never fabricate missing history.

Use owner/prompt/axis filters for REPORT or DIAGNOSTICS. REPORT uses the accepted nested facet and
validated request mapping; records and original report fingerprints remain intact. KNOWLEDGE and
IMPROVEMENTS reject those unsupported filters. Query without them to enumerate the supplied subset.
An empty matching set remains a supplied-subset result, not authoritative owner absence. Extra
reconstruction work may exhaust a lower admitted budget; retrying or supplying a weaker caller
policy does not erase embedded limits. Historical budget counters are not fresh execution credits.
